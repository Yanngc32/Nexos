# Nexo v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Daemon CLI TypeScript dono do histórico, com perfis isolados, troca de motor só com `confirmed`, HTTP localhost e REPL; desktop Tauri consome essa API.

**Architecture:** `packages/shared` tipos. `apps/daemon` é o binário `nexo` (CLI + HTTP + adapters). JSONL em `NEXO_HOME` é fonte da verdade. Engines reais (`claude`/`codex`) e `api` (chat only) atrás do mesmo contrato. Desktop Tauri só fala HTTP 127.0.0.1.

**Tech Stack:** Node 22, pnpm workspaces, TypeScript, Vitest, Hono + `@hono/node-server`, Tauri 2 (última fatia).

  return process.env.NEXO_HOME ?? join(homedir(), ".nexo");

export function ensureHome(root = nexoHome()): string {
  for (const dir of [
    root,
    join(root, "profiles"),
    join(root, "threads"),
    join(root, "run"),
  ]) {
    mkdirSync(dir, { recursive: true });

  return root;

  return join(root, "threads", `${id}.jsonl`);
}

export function configPath(root = nexoHome()): string {
  return join(root, "config.json");
}

export function tokenPath(root = nexoHome()): string {

`Engine` interface:

```ts
import type { EngineEvent, StartOpts } from "@nexo/shared";

export type EngineHandler = (ev: EngineEvent) => void;

export interface Engine {
  start(opts: StartOpts, onEvent: EngineHandler): Promise<void>;
  send(text: string): Promise<void>;
  abort(): Promise<void>;
}
```

`StubEngine`:
- `start` guarda opts (inclui `contextPack`) e `onEvent`
- `send`: se text `== "QUOTA"` emite `quota`; se `== "CRASH"` emite `error` + simula crash; senão emite `text` `"echo:"+text` depois `done`
- expõe `lastStart` pra assert de cwd/env

`session.ts` (orquestração por thread):
- map `threadId -> { engine, profileId, live, assistantBuf, retryCount, pendingQuota }`
- `postMessage(threadId, text, home)`:
  1. lock thread (wait 10s)
  2. append user **antes** de send
  3. se !live, pack + start
  4. send
  5. on `text` buffer; on `done` append assistant, clear buf; on `quota` NÃO switch, set pendingQuota + suggestFallback; on `error` retry uma vez mesmo perfil (start de novo + re-send); segunda error append error event
- `switchThread(threadId, { profileId, confirmed, reason }, home)`:
  1. `assertSwitch`
  2. perfil deve `ready` senão throw 409
  3. abort
  4. append switched (resume true se havia assistantBuf não vazio — quota no meio)
  5. pack, start novo engine
  6. se resume, `send("Continue de onde parou.")` uma vez
- `createEngine(profile)`: stub | api | claude | codex

Test session:
1. user+echo, JSONL tem user depois assistant, sem api key no arquivo
2. `QUOTA` não cria `switched`
3. switch confirmed cria `switched` e segundo start recebe contextPack contendo a user msg
4. switch `confirmed: false` throw

Lock: `withThreadLock(id, fn)` mutex in-memory.
